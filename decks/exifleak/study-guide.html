Writing style

The text follows the ASD-STE100 rules as far as possible. Sentences are short. Each sentence has one idea. Each word has one meaning. This is not an official check. Technical names such as grep and awk stay as they are.

Fixed terms: a tag is the name of a metadata item, for example Artist. A value is the data of a tag. A leak is a tag that tells a reader something private. A detector is a function that looks for one type of leak. To scan is to run the script without -s. To scrub is to run it with -s.

01 Concepts you need

Learn these ideas first. The code is simple when the ideas are clear.

Metadata and EXIF

Metadata is data about data. A photo has pixels. It also has facts about the photo: when, where, and with which device.

EXIF is one standard for these facts. The name means Exchangeable image file format. Cameras and phones write it into JPEG files and other image files. The newest version, Exif 3.0, adds UTF-8 text Source IPTC.

The slide shows five lines that the script hunts: GPS Position, Camera Model Name, Serial Number, Artist, and Software Deck. The script also reads Owner Name Tested.

Where the block sits in a JPEG

A JPEG file is a list of segments. Each segment starts with a marker. The EXIF block lives in an APP1 segment. Inside it, the data uses the TIFF layout: one header, then tables called IFDs (image file directories). The GPS data has its own IFD.

ExifTool prints the byte order of the block. In my test file it printed Exif Byte Order : Big-endian (Motorola, MM) Tested. MM means big-endian. II means little-endian.

GPS: from degrees to a map link

The GPS IFD stores a latitude as three numbers and one letter. The numbers are degrees, minutes, and seconds. The letter is N or S. Longitude works the same way with E or W.

A map link needs one decimal number for each axis. One degree has 60 minutes. One minute has 60 seconds. So one degree has 3600 seconds. This is why the script divides by 60 and by 3600.

13 deg 21' 9.00" N, 74 deg 47' 34.08" E Deck13 + 21/60 + 9/3600 = 13.352574 + 47/60 + 34.08/3600 = 74.792813.3525,74.7928
33 deg 52' 4.00" S, 151 deg 12' 30.00" W Tested33.8678, then the sign flips151.2083, then the sign flips-33.8678,-151.2083

Precision. The script prints four decimal places. One step of 0.0001 degree of latitude is about 11 metres Analysis. That is enough to point at one house.

GPS Position. ExifTool builds the GPS Position line from the separate latitude and longitude tags. It is a composite tag. It appeared in my test output after the separate tags Tested.

What is ExifTool?

ExifTool is a free command-line program by Phil Harvey. It reads and writes metadata in many file types. exifleak does not parse EXIF bytes itself. It asks exiftool for the text and works on that text.

This choice has a result. The script is short, and it works for many file types. But the script depends on the label text that ExifTool prints. If ExifTool changes a label, a grep in the script can fail.

How to add a detector

Add a time detector. You change two places. Everything else stays the same.

  1. Write the function above inspect.
  2. Add its name to the DETECTORS string.

C. The location detector

lines 15 to 25

This is the longest function. It does two jobs: print the raw GPS line, then build a map link.

Define detect_location.

Print the raw line with show. Example: GPS Position : 13 deg 21' 9.00" N, 74 deg 47' 34.08" E.

Start a pipeline that fills maps:

  • grep "^GPS Position" picks the GPS line. There is no -i here. ExifTool always prints this exact text.
  • cut -d: -f2- cuts the line at each colon (-d:) and keeps field 2 and all fields after it (-f2-). The first colon is the one after the label. So only the value remains.
  • tr -d "\"'," deletes three characters: the double quote, the single quote, and the comma. After this, the text is 13 deg 21 9.00 N 74 deg 47 34.08 E.
  • The | at the end of the line tells bash that the command continues on the next line.

awk reads the line and cuts it at spaces. Field $1 is the first word, $2 the second, and so on.

  • $1 = 13 · $2 = deg · $3 = 21 · $4 = 9.00 · $5 = N
  • $6 = 74 · $7 = deg · $8 = 47 · $9 = 34.08 · $10 = E

Latitude is degrees + minutes/60 + seconds/3600. Longitude uses fields 6, 8, and 9. The semicolon separates two statements. awk turns text such as "21" into a number when you do a sum.

If the letter is S, make latitude negative.

If the letter is W, make longitude negative.

printf "%.4f,%.4f\n" prints two numbers with four digits after the point. A comma goes between them. \n ends the line. Then } ends the awk block, ' ends the awk program, and ) closes $(. The result goes in maps.

If maps is not empty, there was a GPS tag. If the photo has no GPS tag, grep prints nothing, awk prints nothing, and maps stays empty Tested.

Print the map link. The variable maps holds only the two numbers. The rest of the link is plain text.

End of the if.

End of the function.

Why is the pipeline so long?

ExifTool prints degrees as text such as 21' and 9.00". A map link needs plain numbers. So the script removes the marks and then does the sum in awk. This is the only place with arithmetic.

Streams and redirection

Each process has three streams. Stream 0 is input. Stream 1 is normal output. Stream 2 is error output. A pipe joins stream 1 of one command to stream 0 of the next. A redirect sends a stream to a file.

CodeLineNormal outputErrors
meta=$(exiftool "$1" 2> /dev/null)42Captured in metaDropped
exiftool -ver > /dev/null 2>&164DroppedDropped
exiftool -overwrite_original -all= "$1" > /dev/null 2>&154DroppedDropped
Order matters

> /dev/null 2>&1 reads left to right. First, stream 1 goes to the null device. Then stream 2 goes to where stream 1 goes now, which is the null device. Both are hidden. The reverse order, 2>&1 > /dev/null, sends errors to the old stream 1 (the screen). In my test the error message still appeared Tested.

09 Question bank

Likely questions, grouped by angle. Open a question to see a short answer. Use the search box to find a word.

A. Concepts 7 questions

What is EXIF?

EXIF means Exchangeable image file format. It is a standard for tags that a camera or phone stores in an image file. Examples are the time, the camera model, and the GPS position.

What is the difference between metadata and EXIF?

Metadata is the general word. It means data about data. EXIF is one family of metadata. XMP and IPTC are two other families. See the table in part 01.

The script reads text from ExifTool, so it can show tags from any family. But its detectors look for only a few names. XMP and IPTC names were not found in my test Tested.

Who writes the EXIF block?

The camera or phone writes it when you take the photo. Editing programs can add or change tags later. Anyone can also write tags with a tool such as ExifTool.

Does every photo have GPS data?

No. The second photo in the demo has only a camera model. The camera app writes GPS tags only if it has the position. Turning off location for the camera app stops new GPS tags Analysis.

Can I see EXIF without a special tool?

Yes. Many file viewers show some tags. On macOS, Preview has an inspector. On Windows, the file properties have a Details tab. Menu names change with the version Analysis. These viewers show fewer tags than ExifTool.

Why does a camera write all this?

The tags help programs sort, show, and edit photos. Examples are the orientation, the time, and the place on a map. The privacy risk is a side effect Analysis.

What is a geotag?

A geotag is a set of GPS coordinates stored in a photo. In the script it is the GPS Position tag.

B. Privacy and risk 9 questions

Who can read the metadata of my photo?

Anyone who gets the file or a copy of it. They only need a tool such as exiftool. They do not need a password.

Does Instagram remove it?

The deck says Instagram, Facebook, X, and Signal usually strip the tags on upload Deck. The word is "usually". Behaviour changes with the app and version. Test with your own file README.

If a platform strips EXIF, am I safe?

Only for the copy that the platform shows. The deck does not say what the platform keeps. Copies that you sent by email or cloud link still hold the tags.

Does turning off location in the camera app solve this?

It helps for new photos, because no GPS tag is written. Old photos keep their tags. Other tags remain: the model, the serial number, a name, and the software Analysis.

Is a serial number dangerous?

By itself it is not a name. But it identifies one device. Two photos with the same serial number came from the same device. That can link photos that look unrelated Analysis.

Can EXIF data be faked?

Yes. Anyone can write any tag with one command. I wrote the GPS tags of my test photos this way Tested. McAfee said he faked the data in his photo Deck. Treat EXIF as a lead, not as proof.

Does the scrub fix photos that I already shared?

No. It changes only the file you run it on. Copies that other people hold keep their tags. So scrub before you share.

Is it right to run this tool on other people's photos?

The tool is for your own files. Reading the tags of a file that someone gave you is a normal thing to do. Using it to find or follow a person is not Analysis.

Why these four types of leak?

They match the harm in the cases: place, device, identity, and software. Slide 2 lists the five lines that the script hunts Deck. Each type is one function, so you can add more.

C. Code and shell 26 questions

Why is exiftool called only one time for each file?

One call is faster than one call for each tag. Also, all detectors then read the same text. The text stays in the variable meta Deck.

Why are there quotes in echo "$meta"?

The quotes keep the line breaks. Without them, all lines join into one line. Then ^Artist cannot match, and every file prints "clean". I got 0 matches without the quotes and 1 with them Tested.

What does grep -i "^$2" do?

It keeps lines that start with the text in $2. The ^ means "start of line". The -i ignores case. So Camera Model matches the line Camera Model Name.

Why head -1?

More than one line can start with the same text. head -1 keeps the first one only. The report then has one line for each look-up.

What does tr -s ' ' do?

It squeezes each run of spaces into one space. ExifTool pads the tag name with many spaces so the colons line up. After tr -s, the line reads Artist : Anish Shobith.

What is $( )? How is it different from backticks?

$( ) runs a command and gives its output as text. Backticks do the same job in an older form. $( ) is easier to read and can nest. The script uses only $( ) Analysis.

What are $#, $0, $1, $?, and "$@"?

$#: the number of arguments. $0: the name of the script. $1: the first argument. $?: the exit status of the last command. "$@": all arguments, each as one word.

Inside a function, $1 and $2 are the arguments of that function, not of the script.

What does 2> /dev/null do?

It sends error messages (stream 2) to /dev/null, which drops them. Normal output stays. On line 42 this keeps the screen clean. But it also hides real errors. This is the cause of the false "clean" Tested.

Why is it > /dev/null 2>&1 and not the other way round?

The shell reads redirects from left to right. First stream 1 goes to the null device. Then stream 2 follows stream 1 there. In the other order, errors go to the screen. I saw the error message in my test Tested.

What does shift do?

It drops the first argument. The second becomes the first, and so on. After shift on line 73, "$@" holds only files and folders, not -s.

What do extglob and nocaseglob do?

extglob allows the pattern @(jpg|jpeg|png|heic|tiff). It means "one of these". nocaseglob makes patterns ignore case. So UPPER.JPG matches jpg Tested.

Why does the loop test [ -f "$file" ]?

When no file matches, bash keeps the pattern as plain text. The test stops the script from running inspect on that text. It also skips folders that have an image extension Analysis.

How does $action "$file" work?

The variable holds a function name, inspect or scrub. The shell replaces $action with that name and then runs the function with the file as $1. It is the same trick as the DETECTORS list.

Why is DETECTORS a string and not an array?

A string is the simplest form. The shell cuts it at spaces when you leave $DETECTORS without quotes. The README says the script uses no arrays, so it stays simple to read README.

Why does the script not use set -e?

An earlier draft used it. A detector ended with present X && emit .... When the test failed, the status was non-zero, and set -e ended the scan at the first photo without a Software tag README.

Why [ ] and not [[ ]]?

Both work in bash. [ ] is the older form. The script needs only simple tests, so it uses the simple form Analysis.

Why echo and not printf?

The text is a fixed label and a line from ExifTool. echo is enough. printf is safer for arbitrary text. The script uses printf inside awk because it needs a number format Analysis.

Why does awk use fields $1 to $10?

After the clean-up, the line is 13 deg 21 9.00 N 74 deg 47 34.08 E. It has ten words. Words 1, 3, and 4 are the latitude numbers. Word 5 is the letter. Words 6, 8, and 9 are the longitude numbers. Word 10 is the letter. Words 2 and 7 are the text deg.

What if the position is south or west?

The two if lines in awk make the number negative when the letter is S or W. A test with a position in the south and west gave -33.8678,-151.2083 Tested.

Why %.4f?

It prints four digits after the point. This is about 11 metres of latitude. It is enough to find a house, and the link stays short Analysis. For more detail, use %.6f.

How does the script handle spaces in file names?

Every use of a file name is in double quotes. A test with my folder/my photo.jpg worked for scan and scrub Tested.

Why is the variable called maps, when it holds only numbers?

It is used to build the map link on line 23. A better name is coords Analysis.

How can a pipeline continue on the next line?

A | at the end of a line tells bash that the command is not complete. Bash then reads the next line as the next part of the pipeline. Lines 17 to 21 use this.

What does cut -d: -f2- do?

-d: sets the separator to a colon. -f2- keeps field 2 and all fields after it. The first colon is the one after the label. So the label is removed and the value stays.

Does it run on Linux?

It uses bash, grep, head, tr, cut, awk, and ExifTool. All of these exist on Linux. I tested only on macOS Analysis.

What is the exit status of the script?

It is 1 for no arguments or no ExifTool. Otherwise it is the status of the last command that ran. A scan that finds leaks still ends with 0. An empty folder ends with 1 Tested.

Which shell features does the script use?

The README lists them: grep -i, head, cut, tr, awk, [ ] tests, if, for, $1 $# $0 $?, 2> /dev/null, extended globs, and ExifTool. Functions, $( ), and shift are the only structure beyond plain sequences README.

D. Design 9 questions

Why a list of detector names?

The loop does not name any check. To add a check, write a function and add its name. To remove a check, delete the name Deck.

How do I add a new detector?

Write detect_time() { show TIME "Date/Time Original"; } on separate lines. Add detect_time to the DETECTORS string. Part 03 has the full code. I ran it and got a [TIME] line Tested.

Why does show print and not return a value?

A shell function can return only a number from 0 to 255. Text must go out through standard output. The caller then captures it with $( ) Analysis.

Why save the report in a variable before printing?

The script must know if the report is empty. If it is, the script prints "clean". The side effect: nothing appears until all detectors end.

Why parse labels? Why not ask ExifTool for exact tags?

You can: exiftool -s -Model -Artist FILE gives names such as Model. The deck lists this as a fix for the brittle labels Deck. The label approach shows how a pipeline works, which is the topic of the talk.

Why does the script not go into subfolders?

Recursive globbing (**) needs bash 4. macOS ships bash 3.2. The script must run on both Deck. The find command is another way Analysis.

Why Bash and not Python?

The talk is about shell scripting. A pipeline of small tools is the point. A Python version is more robust, but it does not show the same ideas Analysis.

Why not write a custom EXIF parser?

EXIF has many tag types, byte orders, and vendor extensions. ExifTool already handles them for many file types. The script reuses it Analysis.

Why a variable and not a temporary file for the ExifTool text?

A variable needs no clean-up. A temporary file needs a safe name and a delete step Analysis.

E. Limits and security 9 questions

What is the biggest weakness?

The false "clean". The script hides ExifTool errors. A missing file, a text file, or a name that starts with - all print "clean" Tested. "Clean" must mean only "no detector printed a line".

Is the wipe complete?

No. PDF edits are incremental, so old metadata can stay. -all= also drops the orientation and colour profile of a JPEG Deck. And the picture, the file name, and the file dates stay Tested.

Does the scrub change the picture?

ExifTool rewrites the metadata. I expect it does not re-encode the image data Analysis. I did not compare the pixels. The file size changed from 1128 to 680 bytes in my test because the tags were removed Tested.

Is it safe to run the script on files from strangers?

Only with a current ExifTool. Older versions had remote code execution (CVE-2021-22204, before 12.24) and filename injection (CVE-2022-23935, before 12.38) Deck. Even a new version can have other bugs. For hostile files, use a separate account or a virtual machine Analysis.

What does "clean" mean?

No detector printed a line. It does not mean the file has no metadata. In my test, a file with Make, lens, date, and copyright tags printed no leak lines from those tags Tested.

Can the scrub delete my only original?

Yes. With -s the change is in place and no backup is made Tested. Copy the file first if you need the tags later.

What is a false negative?

It is a result that says "no problem" when a problem exists. The false "clean" is a false negative.

How accurate is the map link?

Four decimal places give about 11 metres Analysis. The real accuracy also depends on the GPS fix of the phone. And a person can edit the tags.

What does the script not detect?

It does not read Make, lens tags, dates, Host Computer, Copyright, XMP, or IPTC Tested. It does not report altitude or direction. It does not look at the picture or the file name.
